# shared-docs

多人共享的 Markdown 文档，跑在 Cloudflare Pages + D1 上，小范围使用免费额度就够（见「免费额度」）。不需要登录：新建后得到一个只读链接和一个编辑链接，拿到编辑链接的人就能改。

| 路径                      | 内容                                                               |
| ------------------------- | ------------------------------------------------------------------ |
| `/`                       | 文档首页（新建文档、本设备创建过的文档）                           |
| `/doc/new`                | 新文档：空白编辑器，第一次保存时才真正创建，之后地址栏换成编辑链接 |
| `/doc/{id}`               | 只读链接                                                           |
| `/doc/{id}?key={editKey}` | 编辑链接                                                           |

## 目录

| 路径                 | 用途                                                                                      |
| -------------------- | ----------------------------------------------------------------------------------------- |
| `public/`            | 静态文件（文档首页、编辑页、样式、脚本）                                                  |
| `public/_redirects`  | 让所有 `/doc/...` 地址都打开同一个编辑页（静态层改写，不经过 Worker）                     |
| `functions/`         | 接口（Pages Functions），按文件路径自动成为路由                                           |
| `lib/store.js`       | 所有数据库读写（含 D1 表结构）都在这里                                                    |
| `lib/util.js`        | 接口共用的工具。`lib/` 放在 `functions/` 外面，否则也会被当成路由                         |
| `scripts/build.mjs`  | 生成要发布的 `dist/`（`npm run build`，Cloudflare 构建时自动执行）                        |
| `scripts/vendor.mjs` | 把第三方依赖从 `node_modules` 复制到 `public/vendor/`，并修改 Vditor 的几处代码（见下文） |
| `package.json`       | 第三方依赖的版本（Vditor 编辑器、Lucide 图标），以及本地调试用的绑定参数                  |

仓库里**故意没有 `wrangler.toml`**：有了它 Pages 会以它为准，数据库 ID 就得写进仓库。现在构建设置和绑定都在 Dashboard 里配（见下文），不要把它加回来。

## 部署

把 GitHub 仓库连到 Cloudflare Pages 之后（步骤见下文），**推送到 `main` 就会自动部署**，一两分钟后生效。部署进度和构建日志在 Pages 项目 →「部署」里看。

云端构建时 Cloudflare 会先自动 `npm ci` 装依赖，再执行 `npm run build`，然后发布 `dist/`：

- `public/` 里的所有文件都会发布，不需要维护清单
- 第三方文件（Vditor、图标）从 `node_modules` 复制进来，见下文「第三方依赖」
- 给 HTML 里引用的 `/assets/*` 加上内容哈希（`site.css?v=…`）：在 `xxx.pages.dev` 上浏览器每次都会重新验证文件，但绑了自定义域名后，域名的「浏览器缓存 TTL」设置（默认 4 小时）会让浏览器直接用缓存里的旧 CSS/JS，部署后访客可能拿到“新 HTML + 旧 CSS”。加了哈希，文件一改地址就变，部署后立即生效
- `functions/` 由 Pages 自己编译，并自动生成 `_routes.json`，只让 `/api/...` 接口走 Worker。其余请求（首页、文档页、样式、Vditor 文件）都按静态文件返回，文档页 `/doc/...` 靠 `public/_redirects` 改写到编辑页

想在本地确认构建结果，可以自己运行 `npm run build` 看看 `dist/`（已被 git 忽略）。

### 第一次：建 Pages 项目、绑数据库和域名（只做一次）

1. 把代码放到你自己的 GitHub 仓库（fork 这个仓库，或者复制一份推上去）
2. dash.cloudflare.com → **存储和数据库 → D1** → 创建数据库，名字随意（比如 `shared-docs`）。不用建表，代码第一次访问时会自动建好
3. **Workers & Pages** → 创建 → **Pages** → **导入现有 Git 存储库**，选第 1 步的仓库（第一次会要求授权 Cloudflare 访问你的 GitHub）
4. 项目名随意，它只决定 `xxx.pages.dev` 这个默认地址，建好后不能改
5. 构建设置：
   - 框架预设：**None**
   - 构建命令：**`npm run build`**
   - 构建输出目录：**`dist`**（不要用默认的 `/`，否则会把整个仓库发布出去，首页反而是 404）
   - 根目录、环境变量：留空
6. **保存并部署**。这次部署能成功，首页也能打开，但新建文档保存时会提示「没有绑定 D1 数据库」，因为还没绑，继续下一步
7. 进入项目 → **设置 → 绑定** → 添加 → **D1 数据库**：变量名 **`DB`**（一字不差），数据库选第 2 步建的那个
8. 绑定只对**之后的**部署生效：项目 → **部署** → 最新那次部署右边的 **⋯** → **重试部署**
9. （可选）项目 → **自定义域** → 添加你自己的域名

绑定分「生产」和「预览」两套环境。只往 `main` 推送的话只用得到生产环境；如果以后推送别的分支，那些分支会部署到预览环境，要在预览环境里同样绑一次才能用（绑同一个数据库的话，预览环境写的就是线上数据）。

以后要换数据库或改构建设置，也是在 **设置** 里改，改完同样要重试一次部署才生效。

### 第三方依赖（自托管）

站点不从任何外部 CDN 加载东西，第三方文件都放在自己的 `/vendor/` 下：

| 依赖                                           | 用途                               |
| ---------------------------------------------- | ---------------------------------- |
| [Vditor](https://github.com/Vanessa219/vditor) | 文档编辑器和只读页的渲染           |
| [Lucide](https://lucide.dev/)                  | 图标（只复制 `site.css` 里用到的） |

版本写在 `package.json`，`scripts/vendor.mjs` 负责把用得到的文件复制到 `public/vendor/`（不进 git，构建和本地调试时自动生成）。

Vditor 只带了常用部分（解析引擎、中文界面、代码高亮、KaTeX 数学公式、Mermaid 流程图），没带 echarts 图表、graphviz 等大件，文档里出现这类代码块时按普通代码显示。Mermaid 有 3.5 MB，但 Vditor 只在文档里真有 mermaid 代码块时才下载它，没有图的文档打开速度不受影响。

**构建时对 Vditor 的修改**：`scripts/vendor.mjs` 复制完 Vditor 后，会替换 `index.min.js` 里几处写死的代码（只改 `public/vendor/` 里的副本，`node_modules` 不动）。前两处是安全问题：只读链接会分享给别人，而读者的浏览器里存着他们自己文档的编辑密钥（「我创建的文档」列表），所以图里的内容一律不能当作代码执行。

- **Mermaid 安全级别改成 `strict`**：Vditor 写死了宽松的 `securityLevel:"loose"`，允许图里嵌 HTML 和点击事件
- **转义图的报错信息**：图有语法错误时，Vditor 把 Mermaid 的报错信息当 HTML 插进页面，而报错信息会引用图的源码，不转义的话源码里的 HTML 标签会变成真的页面元素
- **图始终按浅色渲染**：Vditor 只在画图那一刻决定深浅色，切换明暗后已经画好的图不会重画。改成始终画浅色，夜间模式下由 `site.css` 用滤镜反色显示，切换立刻生效，打印出来也总是浅色
- **字数统计不算图**：Vditor 只在「所见即所得」模式下统计字数时去掉了渲染好的图和公式，「即时渲染」模式下插一张流程图，字数就会多出几千

每一处都要求恰好找到一次，找不到（通常是升级 Vditor 后代码写法变了）构建就报错，免得补丁悄悄失效。

**升级 Vditor**：改 `package.json` 里的版本号，`npm install`，再把 `public/editor.html` 里两处 `/vendor/vditor-x.y.z/` 改成新版本（改漏了构建会报错提醒）。如果构建报「应当恰好有 1 处」，到新版的 `node_modules/vditor/dist/index.min.js` 里找到对应代码的新写法（Mermaid 的几处在 `mermaid.initialize`、`mermaid.render` 附近，字数统计在 `counter.type` 附近），更新 `scripts/vendor.mjs` 里的替换表；新版已经修好了的（比如自己改成了 `strict`），删掉那一行即可。

## 本地调试

需要 [Node.js](https://nodejs.org/) 20 或更新版本。第一次先装依赖：

```bash
npm install
```

之后每次：

```bash
npm run dev
```

第一次运行时 npx 会问要不要下载 wrangler（Cloudflare 的命令行工具），输入 `y` 回车即可。

打开 http://localhost:8788 。本地用的是模拟的 D1（绑定写在 `package.json` 的 `dev` 命令参数里），数据存在 `.wrangler/state/`（已被 git 忽略），和线上互不相通，可以随便折腾。

查看本地数据库：因为没有 `wrangler.toml`，`wrangler d1 execute --local` 用不了。可以直接用 SQLite 工具（比如 [DB Browser for SQLite](https://sqlitebrowser.org/)）打开 `.wrangler/state/v3/d1/miniflare-D1DatabaseObject/` 下那个名字很长的 `.sqlite` 文件（不是 `metadata.sqlite`）。

## 功能

- 点「新建文档」打开的是空白编辑器，第一次保存时才在服务器上创建（同时出现链接栏和「历史」）；什么都没写就关掉，不会留下任何记录
- 编辑器是 Vditor，默认「所见即所得」（像 Word，不会 Markdown 也能用），工具栏里可切换「即时渲染」「分屏预览」，选择会记住
- 工具栏的「流程图」按钮插入一个流程图模板，改改方括号、花括号里的文字就能用（手机上工具栏太窄，没放这个按钮）。图用的是 [Mermaid](https://mermaid.js.org/)，会写的话时序图、甘特图等也能画，写成 `mermaid` 代码块即可
- 停止输入 1.5 秒后自动保存（Ctrl+S 立即保存）；可以导入或拖入 `.md` 文件，从网页 / Word 粘贴会尽量保留格式
- 下载为 `.md`；需要 PDF 的话用浏览器打印（Ctrl+P → 另存为 PDF），打印时只输出文档正文（代码高亮、公式、流程图照常打印）
- 编辑模式下顶栏下方列出只读链接和编辑链接，可一键复制；收起后点顶栏的「链接」再展开
- 右上角显示在线人数（最近 1 分钟内有心跳的访客，包括只读访客）
- 别人保存的新内容最多 15 秒后自动同步过来；自己有未保存的修改时先不同步，保存时再处理冲突
- 夜间模式：默认跟随系统，点顶栏的月亮 / 太阳按钮切换后会记住选择。流程图在夜间模式下反色显示
- 「历史」保留最近 50 个版本：同一个人连续编辑时每 2 分钟最多留一个版本，换人保存一定会新开一个版本，所以保存冲突时被覆盖的内容总能找回
- 两个人同时改时，后保存的人会收到提示，选择覆盖或加载最新版本
- 没有登录系统：拿到编辑链接的人就能编辑；文档也没有删除功能

## 自定义

- 文档首页右上角的「返回主页」按钮写在 `public/index.html` 里，链接指向作者的个人主页。自己部署时改成你的网址，不需要就删掉这一行
- 配色在 `public/assets/site.css` 开头的 CSS 变量里，浅色 / 深色两套主题各一组基础色，其余颜色都由它们推算

## 数据存在哪里

| 位置                             | 内容                                                                                                |
| -------------------------------- | --------------------------------------------------------------------------------------------------- |
| **Cloudflare D1**（绑定名 `DB`） | 所有文档数据，表结构见 `lib/store.js`。在 Dashboard 的 D1 → 该数据库 → 控制台里可以直接写 SQL 查询  |
| `docs` 表                        | 当前内容、编辑密钥、更新时间                                                                        |
| `history` 表                     | 历史版本，每篇最多 50 条                                                                            |
| `presence` 表                    | 在线心跳，离线超过 2 分钟的记录会被顺手清掉                                                         |
| **访客浏览器 localStorage**      | 「我创建的文档」列表（含编辑密钥）、匿名 ID、明暗和编辑模式偏好。只在那台设备上，清浏览器数据就没了 |

编辑密钥只存在数据库和创建者的浏览器里，丢了就无法再编辑，可以在 D1 控制台里查回来：

```sql
SELECT edit_key FROM docs WHERE id = '文档ID';
```

D1 自带「时间旅行」：可以把整个数据库恢复到过去某个时间点（免费版 7 天内，付费版 30 天内），误操作了能救回来。恢复要用命令行，先 `npx wrangler login` 登录 Cloudflare，再执行下面的命令（`<数据库名>` 换成你建的 D1 数据库名；会覆盖当前数据，先看清楚再执行）：

```bash
npx wrangler d1 time-travel restore <数据库名> --timestamp=2026-09-25T08:00:00+08:00
```

## 接口

| 接口                          | 说明                                                                                                              |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `POST /api/doc`               | 新建文档，body `{ content, anonId? }`，返回 `docId`、`editKey`、`updatedAt`。前端在新文档第一次保存时才调用       |
| `GET /api/doc/:docId`         | 读取内容（不返回 editKey）                                                                                        |
| `POST /api/doc/:docId`        | 保存，body `{ editKey, content, baseUpdatedAt?, anonId? }`；别人先改过则返回 409                                  |
| `GET /api/doc/:docId/history` | 历史版本列表；`?at=<updatedAt>` 取某个版本全文                                                                    |
| `POST /api/presence/:docId`   | 心跳，body `{ anonId }`，返回在线人数和文档当前的 `updatedAt`（前端据此判断要不要拉取新内容）；文档不存在返回 404 |
| `GET /api/presence/:docId`    | 只读取在线人数（前端没用到，心跳接口已经顺带返回）                                                                |

接口出错时统一返回 `{ error: "..." }`。

## 免费额度

涉及两项免费额度，都是每天 UTC 0 点（北京时间 8 点）重置。**先用完的通常是 Workers 请求次数**。

### Workers 请求：每天 10 万次

`functions/` 里的接口（Pages Functions）底层跑在 Workers 上，每次调用都算一次 Workers 请求。首页、文档页、样式、Vditor 这些静态文件不走 Worker，不计数（见上文 `_routes.json`）。换句话说，**只有 `/api/...` 开头的请求才计数**。

这 10 万次是**整个 Cloudflare 账号共用**的，同一账号下的其他 Worker 也在消耗它。

大致消耗：

- 每个开着的文档页：每 15 秒一次心跳，约**每小时 240 次**。心跳顺带告诉页面文档有没有被别人更新，有更新时才多发一次请求去取全文。切到后台的标签页不发
- 打开文档 2～3 次（读取内容、校验编辑密钥、第一次心跳），保存、看历史各 1 次，和上面比可以忽略

10 万 ÷ 240 ≈ 400 个「标签页 · 小时」，比如 50 个人每天各开 8 小时就差不多到顶。超额后当天所有接口都会报错：页面还能打开，但文档内容加载不出来，也保存不了。

用量可以在 Dashboard 的 **Workers & Pages** 概览页查看。不够用的话，可以升级 Workers 付费版。

### D1：每天 10 万行写入、500 万行读取

- 每次保存：写 2～3 行（文档 + 历史版本，超过 50 个版本时再删掉最旧的）
- 在线人数：每个开着的文档页约 30 秒写 1 行（心跳 15 秒一次，服务端对距上次记录不足 25 秒的心跳不写入）

一个标签页开一小时大约写 120 行，比 Workers 请求次数宽松，一般不会先用完。D1 超额后保存和心跳会失败，查看文档不受影响。

### 防刷

任何人都能调用新建文档接口。心跳接口只接受已存在的文档，编造的文档 ID 会被直接拒绝，不会写进数据库。

但被拒绝的请求也算一次 Workers 请求，有人用脚本狂刷的话，照样能把请求额度提前用完（不会丢数据，第二天自动恢复）。真要防住，就在 Cloudflare 的防火墙里加一条**速率限制规则**，步骤见下一节。

## 给接口加速率限制（可选）

效果：同一个 IP 在 10 秒内请求 `/api/...` 超过一定次数，就把它拦住 10 秒。

- 计数只看 `/api/...` 开头的请求，也就是上面说的全部接口：新建、读取、保存文档，历史版本，心跳。首页、文档页、样式这些静态文件不受影响
- 你分享出去的链接是 `/doc/xxx`，不带 `api`，但打开后页面会在后台自己请求 `/api/...`（读取内容、每 15 秒一次心跳、保存），这些后台请求才是消耗额度的地方，规则拦的就是它们
- 被拦下的请求在防火墙这一层就挡掉了，到不了 Worker，**不消耗 Workers 请求额度**。这是它比在代码里做检查更有用的地方

**前提：先绑自定义域名。** 规则是加在域名上的，`xxx.pages.dev` 默认地址加不了（它也不受这条规则保护，见本节最后）。

步骤（Cloudflare 界面经常调整，菜单名以实际看到的为准）：

1. dash.cloudflare.com → 选你的**域名**（不是 Pages 项目）→ **安全性 → 安全规则**（Security rules；旧版界面是 **安全性 → WAF**）
2. **创建规则 → 速率限制规则**（Rate limiting rules）
3. 规则名称随意，比如「限制接口请求」
4. **如果传入请求匹配**：字段选 **URI 路径**，运算符选 **开头为**（starts with；列表里没有的话选 **包含**），值填 `/api/`
5. **具有相同特征**：**IP**（免费版只有这一项）
6. **当速率超过**：请求数填 **20**，期间 **10 秒**（免费版只能选 10 秒）
7. **然后执行**：**阻止**（Block），持续时间 **10 秒**（免费版只能选 10 秒）
8. **部署**

阈值为什么是 20：正常访客每个标签页 15 秒才一次心跳，打开文档时一下子也只有 2～3 次；留宽一点，是因为同一个公司、学校的网络里，很多人可能共用一个出口 IP，他们的请求会算在一起。如果有人反映被误拦，就把数字调大。

加好后，可以在 **安全性 → 事件**（Security events）里看到被拦下的请求。

免费版每个域名只能建 1 条速率限制规则。

**别忘了 `xxx.pages.dev`**：绑了自定义域名之后，默认地址仍然能访问，而且不经过你域名上的规则，别人可以绕过限制直接刷它。Cloudflare 官方的做法是用「批量重定向」（Bulk Redirects）把整个 `xxx.pages.dev` 301 跳到你的域名，跳转同样在 Worker 之前完成，不消耗额度。步骤见官方文档：[Redirecting *.pages.dev to a custom domain](https://developers.cloudflare.com/pages/how-to/redirect-to-custom-domain/)。
